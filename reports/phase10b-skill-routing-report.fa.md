## رجیستری مهارت‌ها

رجیستری فاز ۱۰الف همچنان مرجع دوازده playbook واردشده است. فایل `skills/software-delivery/role-skill-map.json` سیاست واحد نقش به مهارت است و `services/orchestrator/app/skill_routing.py` آن را مصرف می‌کند. شناسهٔ ناشناخته رد می‌شود و metadata خارجی `allow_implicit_invocation` نمی‌تواند مهارتی را فعال کند.

## ماتریس نقش و مهارت

سیاست مسیریابی نقش‌های نیازمندی، مدیریت پروژه، UX، معماری، Backend، Frontend، پیاده‌سازی، یکپارچه‌سازی، امنیت، تست، رفع اشکال، DevOps، بازبینی، راستی‌آزمایی انتشار و نقش‌های مدیریتی را پوشش می‌دهد. قوانین شرطی مانع انتخاب مهارت‌های UI، پایگاه‌داده، امنیت و استقرار بدون شواهد در متن کار یا پروژه می‌شوند.

## روتر مهارت

`SkillRouter` نوع پروژه، هدف، نیازمندی‌ها، ریسک، فناوری‌ها، فاز، نقش مسئول و مهارت‌های انتخاب‌شدهٔ پروژه را می‌گیرد و انتخاب‌های محدود شامل شناسه، دلیل، اولویت و اجباری/اختیاری را برمی‌گرداند. `route_project` مجموعهٔ متناسب با پروژه را می‌سازد و pipeline دوازده‌مرحله‌ای را به‌صورت اجباری تحمیل نمی‌کند.

## سازگاری وابستگی مراحل

وابستگی فقط برای مهارت‌های انتخاب‌شده ساخته می‌شود. کار صرفاً مستندسازی هیچ مرحلهٔ مهندسی نامرتبطی را فعال نمی‌کند. کار Backend-only می‌تواند از Backend/Database/Test/QA/بازبینی نهایی عبور کند و مرحلهٔ UI ندارد. پروژهٔ Full-stack مهارت‌های مرتبط UI، Frontend، Backend، API، احراز هویت/امنیت، تست/QA و در صورت درخواست استقرار و بازبینی نهایی را فعال می‌کند.

## بارگذاری زمینه

`SkillContextLoader` فقط `SKILL.md` مهارت‌های منتخب و referenceهای اعلام‌شده و صریح را بارگذاری می‌کند. وجود task، نقش و پروژه الزامی است و سقف اندازهٔ فایل اعمال می‌شود. اسکریپت‌ها اجرا نمی‌شوند و state جدیدی ساخته نمی‌شود؛ مرز اجرای اسکریپت همان Agent Worker → Tool Policy → Local Agent است.

## دروازه‌های کیفیت

قرارداد evidence ساختاریافته برای artifact، بررسی‌ها، یافته‌ها، وضعیت gate، handoff و evidence فراهم شده است. نبود شواهد عینی باعث توقف gate می‌شود: تست به نتیجه و command نیاز دارد، QA به evidence رگرسیون، امنیت به رفع یافته‌ها، استقرار به health check و بازبینی نهایی به پذیرش، نبود یافتهٔ بحرانی و check نیاز دارد.

## مدل مجوزها

ابزار مؤثر از اشتراک مجوز نقش، مجوز task، نیاز ابزار مهارت و سیاست سراسری به‌دست می‌آید. playbook نمی‌تواند ابزار جدیدی به نقش بدهد. برای بازبینی مستقل، قابلیت read-only `diff` در metadata بازبینی نهایی ثبت شده است، اما همچنان اشتراک مجوزها محدودکننده است.

## ماندگاری

جدول موجود `agent_tasks` ستون‌های `skill_selections_json` و `skill_trace_json` را با migration idempotent در startup نگه می‌دارد. `db.set_task_skill_route` تصمیم روتر را روی همان task ثبت می‌کند و پاسخ API نیز `skill_selections` و `skill_trace` را ارائه می‌دهد. فراخوانی‌های قبلی task سازگار باقی مانده‌اند.

## محدودیت‌ها

این فاز مسیریابی، انتخاب context محدود، قرارداد evidence، ارزیابی gate و persistence task را فراهم می‌کند. اتصال مهارت‌ها به Agent Worker واقعی و تبدیل stageهای ترتیبی به workflow سراسری در این فاز انجام نشده است.
